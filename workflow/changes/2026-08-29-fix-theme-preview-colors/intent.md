# Intent: 修复主题预览色差并审计全部主题

## Problem

主题详情的大预览把 `rgba()` 颜色解析成纯 RGB，丢失主题声明的透明度，再统一套用预览层的不透明度。以「鲸鱼娘」为例，主题声明的 `rgba(189,153,153,0.16)` 浅色遮罩被预览放大成明显的粉褐色覆盖，导致动态预览与正确的浅蓝色背景、静态预览和真实豆包界面产生很大色差。全部 26 个内置主题的预览可见字段都至少包含一个半透明颜色，因此这不是单个主题的配置问题。

## Proposed outcome

让主题预览在解析和绘制每个颜色时保留其原始 alpha，并与用户选择的界面不透明度正确合成。修复「鲸鱼娘」后，背景仍以浅蓝色为主，棕色只作为小面积强调色；同时自动审计全部内置主题的预览字段，修复同类透明度丢失问题，并确认主题包本身不存在额外的配色声明错误。

## Affected users and systems

- 浏览主题详情、比较预览和应用效果的 macOS 用户与主题作者。
- `crates/skin-core/src/theme.rs` 的预览颜色解析、投影结构和主题回归测试。
- `apps/desktop/src/main.rs` 的主题详情预览颜色合成。
- `themes/*/theme.json` 和 `theme.css` 只接受审计；只有证据确认主题包本身错误时才做最小修正。

## Constraints

- 先用可自动判红的「鲸鱼娘」透明色测试锁定故障，再修改实现。
- 颜色解析必须支持主题标准现有的 `#rrggbb`、`rgb()` 和 `rgba()`，未声明 alpha 时按 `1.0` 处理。
- 每个预览颜色的原始 alpha 必须保留，不能用一个全局固定透明度替代。
- 用户的界面不透明度仍然生效，但必须与主题颜色 alpha 合成，而不是覆盖主题作者的值。
- 修复必须数据驱动，对全部主题使用同一路径，不为「鲸鱼娘」新增专属分支。
- 主题运行时注入和官方应用中的正确配色不得因预览修复而改变。
- 修改主题包时同步生成 Web 主题目录，不手工编辑生成文件。
- 保存当前工作区中与本需求无关的未提交改动。

## Out of scope

- 重新设计主题配色、替换背景画作或生成新的角色资产。
- 让 GPUI 静态预览执行任意主题 CSS 或复制豆包 DOM。
- 改变主题不透明度滑杆的产品含义、范围或默认值。
- 修改豆包/豆包工作的主题注入生命周期、双目标选择或协议桥。

## Success signals

- 「鲸鱼娘」动态预览保留 `chatBackground` 的 `0.16` alpha 和输入框边框的 `0.28` alpha，整体视觉与浅蓝色背景一致，不再被粉褐色覆盖。
- 全部 26 个内置主题的预览颜色审计能验证 RGB 与 alpha 均按当前外观变体解析，且不会退回到丢失透明度的纯 RGB 值。
- 选择若干浅色、深色、有背景和无背景主题做真实窗口对照，动态预览与主题包预览的主色调一致、文字可读。
- 若审计确认某个主题包自身配色错误，只修正被证据锁定的字段，并同步 Web 目录；否则不批量调色。
- 相关核心、桌面、Web（如涉及主题包）与 workflow 检查通过，真实窗口截图无敏感内容。

## Open questions

无。用户确认「鲸鱼娘」应以蓝色主题为准；本变更把明显的暖色覆盖视为预览渲染错误，而不是重新定义主题风格。

## Decision

等待产品负责人确认本意图后进入规格设计；本阶段只完成诊断和可判红复现，不修改产品代码或主题包。
