# Intent: 增加“关于豆包主题”菜单

## Problem

当前 macOS 应用没有注册应用菜单，因此用户无法从系统菜单栏查看产品名称、图标、版本和版权信息。这不符合 macOS 用户寻找应用身份与版本信息的标准路径，也不利于问题反馈时确认实际运行版本。

## Proposed outcome

在菜单栏最左侧的“豆包主题”应用菜单中增加“关于豆包主题”，点击后打开 macOS 原生关于面板，展示正式应用图标、产品名、当前构建版本和版权信息。应用菜单同时保留系统标准的服务、隐藏与退出能力，不在主界面增加重复入口。

## Affected users and systems

- 使用 macOS 桌面主题工具的所有用户。
- `apps/desktop/src/main.rs` 中的 GPUI 应用菜单注册和“关于”动作。
- `apps/desktop/Info.plist` 及打包脚本提供给原生关于面板的应用元数据。

## Constraints

- “关于”必须位于最左侧应用菜单的首项，名称为“关于豆包主题”。
- 使用 macOS 原生标准关于面板，不制作网页、主界面卡片或自定义大弹窗。
- 图标复用当前正式 `AppIcon`，版本读取构建后的 `Info.plist`，不得另外硬编码一套易漂移的版本号。
- 保留标准的“服务”“隐藏豆包主题”“隐藏其他”“全部显示”和“退出豆包主题”菜单行为及系统快捷键。
- 不新增联网请求、更新检查、遥测或外部链接。
- 保存当前工作区中与本需求无关的未提交改动。

## Out of scope

- 新增设置页、帮助中心、更新检查、反馈系统或许可证浏览器。
- 重构主界面导航、标题栏或主题详情布局。
- 为 Windows 或 Linux 设计同名菜单；当前产品与验证范围仅为 macOS。
- 修改应用图标本身。

## Success signals

- macOS 菜单栏出现“豆包主题”应用菜单，其首项为“关于豆包主题”。
- 点击菜单项后只出现一个原生关于面板，重复点击会将现有面板带到前台，不叠加多个窗口。
- 关于面板显示正式图标、“豆包主题”、与打包产物一致的版本号和“Copyright © 2026 豆包主题贡献者”。
- “服务”、隐藏、全部显示和 `Command-Q` 退出继续正常工作。
- Rust、workflow、打包签名检查通过，并在真实打包应用中保存无敏感内容的菜单和关于面板截图。

## Open questions

无。“关于菜单”按 macOS 标准应用菜单理解，不是在主界面增加一个名为“关于”的导航页面。

## Decision

等待产品负责人确认本意图后进入规格设计；本阶段不修改产品代码或打包元数据。
