# Intent: 面向普通用户的主题生产与应用工具链

## Problem

当前主题标准已经定义 `theme.json` v2、`theme.css`、预览图和可选素材的契约，Rust 核心也已经具备主题加载、主题包安装、CDP 在线应用和离线克隆能力，但这些能力分散在桌面界面、示例程序和项目文档中。旧 Python CLI 已退出工作树，仓库里没有正式、稳定、可由 Agent Skill 调用的 Rust CLI，也没有把自然语言主题需求转换为合规主题包、再安全应用到豆包工作的可安装 Skill。

不懂开发的用户因此仍需手写 JSON/CSS、理解目录结构和运行开发命令；豆包工作或其他支持 `SKILL.md` 的 Agent 也无法只靠受控命令完成“制作主题—检查主题—安装/应用主题”的闭环。

## Proposed outcome

提供一套以 Rust CLI 为唯一确定性执行入口的主题工具链，并提供两个职责分离、可安装的 Agent Skill：

- 主题生产 Skill：把用户的自然语言风格要求转换为符合现行主题标准的独立主题目录，调用 CLI 创建骨架、检查并打包。
- 主题应用 Skill：列出、检查、安装、应用和恢复主题，在发生真实副作用前明确目标与动作，并把技术错误翻译为普通用户可执行的提示。
- Rust CLI：复用 `skin-core` 的真实加载、安装和应用路径，不保留 Python 运行时；同时提供机器可判断的退出码和可选 JSON 输出，供 Skill 与其他 Agent 宿主调用。

Skill 应保持标准 `SKILL.md` 目录结构，不依赖 Codex 私有提示；支持该格式且能执行本机二进制的豆包工作版本可以安装并调用它们。对豆包工作 Skill 兼容性的当前事实与限制必须在交付时明确验证或标注。

## Affected users and systems

- 不懂 Rust、JSON 或 CSS，但希望制作个人主题的豆包工作用户。
- 需要确定性创建、检查、打包和应用主题的 Agent 宿主。
- Rust workspace、`skin-core` 主题引擎、用户主题目录和本机豆包工作进程。
- 主题标准、示例包、Skill 资源与分发文档。

## Constraints

- 不修改 `/Applications/DoubaoWork.app`；在线应用只通过回环 CDP，离线模式只操作克隆。
- 默认不读取或转发对话内容、Cookie、账号、工作区、附件、工具或未知内容块。
- 安装包沿用现有路径穿越、符号链接、文件数量、解压大小和校验限制；不降低现有安全边界。
- 主题 ID、目录名、清单、CSS 作用域、必需语义变量、深浅色 variants、素材路径和商店字段遵循当前主题标准。
- 只打包用户有权分发的素材；第三方来源主题保留来源、提交与许可证元数据。
- Skill 默认使用纯色或渐变完成可用主题；需要图片、字体或图标时只使用用户提供、明确生成或许可清楚的素材。
- 面向普通用户的输出使用中文产品语言，不暴露 CDP、端口、注入、签名、内部路径或原始错误栈；开发者模式和 JSON 输出可以保留诊断信息。
- CLI 复用现有 Rust 核心，不复制另一套主题解析器或应用实现。
- 现有工作树包含大量进行中的迁移和主题改动；实现必须只触碰本变更明确拥有的文件并保留其他修改。

## Out of scope

- 不承诺或实现豆包工作官方未公开的 Skill 安装协议、Skill 商店发布或自动分发。
- 不发布主题到线上画廊，不部署网站，不创建发布版本，不修改生产环境。
- 不新增远程模型代理、附件/工具转发或会话内容读取能力。
- 不把主题生产做成新的 GUI 编辑器，也不在本变更重做现有桌面主题选择器。
- 不批量改写现有主题视觉内容。

## Success signals

- 新用户可从一条自然语言需求得到可加载的 v2 主题目录，并通过确定性检查后生成可安装包；无需手写 JSON。
- CLI 能列出主题、创建主题、检查主题、打包主题、安装主题、在线应用主题和恢复默认，并为成功、无效输入与运行失败返回稳定退出码。
- 生产 Skill 和应用 Skill 均通过 Skill 校验，说明其触发边界、授权边界、CLI 发现方式和失败停止条件。
- CLI 的创建、检查、打包和安装行为有自动化回归测试；路径逃逸、目录 ID 不一致、缺失素材、错误 CSS 作用域和不完整双外观配置会被拒绝或给出明确诊断。
- 对真实豆包工作只在独立测试窗口/会话中验证：应用后可观察到 `data-skin` 与关键计算样式变化，恢复后主题标记和注入样式被清理；只监听端口不算成功。
- Rust 与 workflow 的适用检查通过，实际命令、结果、截图或 DOM 证据写入 `verification.md`。

## Open questions

- 豆包工作当前版本是否公开支持可导入的 `SKILL.md` 包，以及它允许 Skill 调用本机二进制的具体安装位置，需要在实现前用当前应用或官方资料核实。若没有公开契约，交付范围保持为可移植 Skill 包和手动安装说明，不声称已在豆包工作内原生安装。
- 最终分发是否需要把 CLI 二进制随 Skill 打包，还是由 macOS 应用安装器统一放置，需要在 Spec 中依据签名、架构与升级路径决定。

## Decision

等待产品所有者审阅。接受本 Intent 只授权进入 Spec，不授权安装 Skill、修改豆包工作、执行真实应用、发布或部署。
