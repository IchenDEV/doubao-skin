# Intent: 完善桌面端 UX

## Problem

用户要求“完善应用的 UX”。通读 `apps/desktop/src/main.rs` 后，确认存在以下具体问题（均已在代码中核实）：

1. **状态反馈不可靠**
   - `message` 是单一全局字符串，切换主题、切换目标应用后不会清除，旧的“已恢复默认”“应用失败”会残留在不相关的主题上。
   - 应用失败只显示“应用失败，请再试一次”，真正原因只写进内部日志（`internal_logs`），用户看不到，也无从判断是“应用未运行”“CDP 连不上”还是别的。
   - `apply_selected` 在后台线程成功前就把 `active_theme` 置位，按钮在应用中即显示“正在使用”，失败后才回滚，状态会闪烁。
2. **“恢复默认”缺少边界处理**：没有任何主题处于应用状态时按钮依旧可点；点击立即执行，没有进行中/完成的明确区分。
3. **主题无法管理**：用户安装的主题无法在界面内删除，也没有“在 Finder 中显示”的入口；只能手动去文件系统清理。
4. **主题商店**：已有加载态、刷新按钮与侧栏“已安装”标记，但错误面板内没有就地重试按钮（重试入口只在顶部），商店卡片/详情不标记“已安装”，已安装主题仍显示“安装”。
5. **键盘与可访问性**：搜索框是通过监听 `key_down` 拼接字符实现的，不支持中文输入法组合输入、光标移动、粘贴和选择；快捷键（⌘F/⌘O/⌘1/⌘2、方向键、回车）没有任何界面提示。
6. **空状态与首次引导**：目标应用未安装时仅在按钮和一行小字提示；没有主题时只显示“还没有可用主题”，没有引导到商店或导入。

## Proposed outcome

在不改变主题协议、主题包格式和注入逻辑的前提下，使主窗口的反馈、管理与引导更清晰：

- 状态消息按“主题 + 目标应用”作用域，切换后不残留；失败时给出用户可理解的原因与下一步建议。
- 应用过程中按钮显示“正在应用…”，只有真正注入成功后才显示“正在使用”。
- “恢复默认”仅在当前目标存在已应用主题时可用；进行中与完成状态明确。
- 用户安装的主题可在界面内删除（带确认），并可在 Finder 中显示；内置主题不可删除。
- 商店错误面板提供就地“重试”；商店卡片与详情标记“已安装”，并将操作改为“重新安装/已安装”。
- 搜索框支持中文输入法、粘贴与光标；快捷键以悬浮提示或菜单项体现。
- 目标应用未安装、无主题等空状态提供明确的下一步引导。

## Affected users and systems

- 使用 macOS 桌面主题工具的用户。
- `apps/desktop`（GPUI 界面、窗口级交互）。
- 可能小幅涉及 `crates/skin-core` 中主题删除/路径的辅助函数与错误分类（仅限新增，且需回归测试）。
- 不影响 `apps/web`、`themes/` 内容、协议桥接和官方应用。

## Constraints

- 保持上一变更确定的固定 `1120 × 720` 窗口（`2026-08-29-disable-window-resizing`），不引入新的窗口尺寸；现有 compact/short 布局代码保留。
- 不修改 `/Applications/DoubaoWork.app` 与 `/Applications/Doubao.app`。
- 不改变主题 manifest 格式、`doubao-skin://` URL 语义或商店 catalog 协议；因此不需要重新生成 web 目录。
- 删除主题只作用于用户主题目录（`theme::user_themes_dir()`）内、且由本工具安装的主题，不触碰其他路径。
- 不新增 Python 源码；不引入含义不明确的第三方素材。
- 原生 UI 变更必须在真实窗口验证（默认尺寸，以及仍保留的窄布局代码路径）。

## Out of scope

- 重新设计整体视觉风格、配色或图标。
- 新增主题编辑器、云同步、账号体系。
- 协议桥接（`protocol_bridge.rs`）及其验收。
- 窗口尺寸可调、响应式重构。
- Web 画廊（`apps/web`）的 UX。

## Success signals

- 切换主题或目标应用后，上一次的“已恢复默认/应用失败”等提示不再出现。
- 模拟“目标应用未运行/CDP 不可达”时，界面显示可读的失败原因，而非通用文案。
- 应用进行中按钮不显示“正在使用”；失败后状态与实际一致。
- 无已应用主题时，“恢复默认”呈禁用态。
- 可删除用户主题（需确认）并从列表消失；内置主题没有删除入口；可在 Finder 中显示。
- 商店错误面板可就地重试；已安装主题在商店卡片/详情标记为已安装。
- 搜索框可输入中文、粘贴，并可用方向键移动光标。
- Rust 相关回归测试、`./scripts/check.sh rust` 与 `./scripts/check.sh workflow` 通过，并有真实窗口截图证据。

## Open questions

1. 搜索框中文输入法与光标支持：GPUI 当前版本是否提供可复用的单行文本输入组件/`EntityInputHandler`？若成本过高，是否接受降级为“支持粘贴 + 尾部编辑”，把完整 IME 作为后续变更？（需在 spec 阶段调研后决定。）
2. 删除用户主题是否需要“撤销”（移入废纸篓）还是直接删除？建议移入废纸篓。
3. 失败原因的分类粒度（应用未运行 / 调试端口不可达 / 注入超时 / 其他）以 `live::run` 现有错误类型为准，是否需要先扩展 skin-core 的错误枚举？

## Decision

等待产品负责人确认本意图（可对范围增减）后，再进入规格设计；本阶段不修改产品代码。
