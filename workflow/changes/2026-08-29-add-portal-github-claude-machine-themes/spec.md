# Spec: 四套辨识度明确的主题包

## Requirements

1. 新增以下四个独立主题包，用户可在现有主题列表中预览、选择和应用：
   - `huaxia-blue` / “华夏蓝”：正式、清晰的中式门户气质。
   - `github-repository` / “代码仓库”：熟悉的 GitHub 产品界面气质。
   - `claude-warm` / “Claude 暖橙”：温暖、安静、以内容为中心的 Claude 气质。
   - `machine-overseer` / “机械工头”：机器人催促人类不停工作的荒诞综艺喜剧气质。
2. 四个主题均采用 v2 manifest，`appearance` 为 `both`，提供完整浅色与深色配置；预览优先外观分别为浅色、深色、浅色、深色。
3. 四个主题均包含 1200 × 675 的 `preview.jpg`，并使用现有主题列表、详情和应用流程，不新增应用专用分支。
4. 仅“机械工头”包含一张原创 `bg.jpg`。其余三个主题只使用纯色或 CSS 渐变，不打包外部图片、字体、标志或角色素材。
5. 用户可见名称和描述使用自然语言，不展示内部 ID、来源字段、许可说明或实现术语。
6. 四个主题的 `store.sortOrder` 依次使用 26–29，不修改现有主题顺序。
7. 四个主题必须分别定义界面字体、正文字体、代码字体、行高、输入框圆角和全局圆角比例；字体与形状是主题辨识的一部分，不能四套共用同一组默认值。

## User experience

### 华夏蓝

- 名称：“华夏蓝”；描述：“深蓝与中国红沉稳搭配，清晰庄重”。
- 浅色以 `#F4F7FB`、`#FFFFFF`、`#172B4D` 为基础，深蓝承担结构层级，`#C62828` 是唯一主强调色。
- 深色以 `#081521`、`#10243A`、`#EEF4FA` 为基础，主强调色调整为 `#EF6A65`。
- 分隔线清楚、圆角克制、阴影很轻；不出现徽章、机关标志、站点抬头或暗示官方身份的文案。
- 界面控件使用苹方等系统黑体，聊天正文优先使用宋体，形成“导航清楚、正文端正”的层级；正文字号比例 1.00、行高 1.65。
- 形状接近方角：全局圆角比例 0.55，输入框 8 px；卡片、按钮和消息气泡保留 4–8 px 安全圆角，不做完全尖锐的直角。

### 代码仓库

- 名称：“代码仓库”；描述：“深灰层级配合蓝绿状态色，专注利落”。
- 浅色使用 `#FFFFFF`、`#F6F8FA`、`#1F2328`、`#D0D7DE`；深色使用 `#0D1117`、`#161B22`、`#C9D1D9`、`#30363D`。
- 主强调色在浅色为 `#0969DA`、深色为 `#2F81F7`；绿色仅用于成功状态和细节点缀，不与主按钮争夺层级。
- 代码字体使用系统等宽字体，组件边界紧凑但不改变应用既有布局。
- 界面与聊天正文使用紧凑的系统无衬线字体，代码使用 `ui-monospace` / SF Mono / Menlo 回退栈；正文字号比例 0.98、行高 1.55。
- 形状采用 GitHub 产品界面常见的小圆角：全局圆角比例 0.65，输入框 10 px；不使用胶囊按钮或大面积柔软圆角。

### Claude 暖橙

- 名称：“Claude 暖橙”；描述：“暖米白与陶土橙安静柔和，适合长时间阅读”。
- 浅色使用 `#F7F3EA`、`#FFFCF5`、`#2D2926`、`#DDD4C8`，主强调色为 `#D97757`。
- 深色使用 `#1F1C1A`、`#2A2521`、`#F4EDE3`、`#4A423B`，主强调色为 `#E58A69`。
- 留白舒展、边框柔和、阴影克制；不使用 Claude 或 Anthropic 标志，不复制其页面结构，也不暗示官方合作。
- 界面与正文使用温和的系统无衬线字体，正文保持较宽松字距和阅读节奏；代码仍使用系统等宽字体；正文字号比例 1.02、行高 1.68。
- 形状明显柔和：全局圆角比例 1.15，输入框 22 px，消息和浮层使用中到大圆角；发送按钮可以是圆形，但带文字的按钮不得做成过度胶囊形。

### 机械工头

- 名称：“机械工头”；描述：“复古综艺舞台上的机器人催工喜剧，荒诞又热闹”。
- 浅色使用 `#D8E2E8`、`#EEF3F5`、`#15222B`；深色使用 `#06131B`、`#0B2431`、`#D9F0F2`；红色 `#C8343E` / `#E5484D` 是唯一主强调色。
- 原创背景表现复古未来综艺舞台上友好机器人催促虚构成年打工人重复劳动的滑稽场景。主体靠画面边缘布置，中部聊天阅读区保持低细节；画面采用高饱和蓝、青、珊瑚红和奶油黄，以及略带颗粒的电视截图质感。不得出现文字、标志、水印、伤害、真实人物肖像或与参考图近似的舞台纹样、角色、动作和构图。
- 内容表面默认不透明度不低于 0.78，并叠加足够遮罩，确保背景不会干扰消息、代码和输入区阅读。
- 界面使用系统无衬线字体，英文、数字和代码优先使用等宽字体，保留机器主题的节奏感；中文回退到苹方以保证可读性；正文字号比例 0.98、行高 1.58。
- 形状最硬朗：全局圆角比例 0.50，输入框 4 px，卡片和消息气泡为 2–6 px 小圆角；不用发光胶囊、锯齿边框或影响点击区域的装饰切角。

## Technical design

### 主题目录

每个主题仅新增 `themes/<id>/theme.json`、`theme.css`、`preview.jpg`；“机械工头”额外包含 `bg.jpg`。不新增代码模块、字体、运行时依赖或主题专用图标。

### Manifest

- 使用 `schemaVersion: 2`、`version: 1.0.0`、`author: 豆包主题`。
- 四个主题均填写 `preview`、`store`、`appearance`、`typography`、`layout`、`composer`、`content`、`effects` 和 `variants.light/dark`。
- 三个无图片主题使用纯色或轻微线性渐变；动画均为 `none`。
- “机械工头”使用 `background.type: image`、`fit: cover`、`animation: none`，并填写 `surfaceOpacity`、`veil`、固定焦点位置。
- “代码仓库”记录 Primer Product UI 的官方来源、实现时固定的上游提交和相应许可；“Claude 暖橙”只记录产品视觉参考地址和访问日期，明确为原创 CSS 适配且不包含第三方资产。

### 字体与形状

- 只使用 macOS 和浏览器可用的系统字体回退栈，不新增字体文件、`@font-face`、远程字体地址或字体网络请求。
- `typography.ui` 控制导航与控件，`typography.body` 控制聊天正文，`typography.code` 控制代码；每个回退栈必须以通用族 `sans-serif`、`serif` 或 `monospace` 收尾。
- 正文行高不低于 1.55，不能通过固定像素字号覆盖用户缩放；中英文、数字、代码和粗体在普通与窄窗口中都不得截断或上下裁切。
- `effects.radiusScale` 统一控制主题形状语言，`composer.radius` 再精确控制输入区；浅色与深色 variant 保持同一形状，不因外观切换改变圆角性格。
- 小圆角主题仍保留清晰焦点环和完整点击区域；圆角只改变视觉轮廓，不缩小按钮、图标或输入区的可操作范围。

### CSS

- 每个文件的所有变量都同时限制在对应的 `html[data-skin="<id>"]` 与 `body` 作用域；深色覆盖也必须带同一主题 ID，禁止使用会影响其他主题的泛化选择器。
- 覆盖现有 `--N*`、`--B*`、`--dbx-*`、`--s-color-*` 和 `--semi-color-primary*` 语义变量，并为需要 raw 值的颜色提供匹配的 RGB 三元组。
- 每个主题只有一个主强调色；hover、active、disabled 均从同一色相派生。
- 正文对背景对比度至少 4.5:1，大号文字至少 3:1；焦点、边框和交互状态在浅色与深色下均可辨认。

### 预览与目录

- 使用现有主题作者工具从 manifest/CSS 生成 16:9 预览，不手工伪造与实际主题不一致的商店图。
- 主题变更完成后运行现有网页同步命令，由它生成 catalog、数据库和 ZIP；不得手改生成目录。
- ZIP 只包含主题声明的文件；用户提供的参考图不得进入主题目录、生成目录或安装包。

## Security and privacy

- 不读取、保存或打包任何会话内容、账号信息、Cookie、工作区数据或附件。
- 不新增网络请求；主题应用仍使用现有 loopback 通道。
- 不修改或替换官方应用资源；真实验证仅通过现有 live 模式临时应用 CSS。
- 不使用国徽、机关标志、GitHub、Claude 或 Anthropic 标志，也不使用来源不明的视觉资产。
- 原创背景不得包含水印、可识别真人或从参考图复制的表达；用户提供的图片只在本次对话中用于理解主题意图。

## Alternatives and non-goals

- 不复刻任何完整站点、导航结构、标志、吉祥物、字标或品牌插画。
- 不改变桌面主题选择器、主题引擎、安装包协议、网页布局或 CDP 生命周期。
- 不新增字体、图标系统、交互动画、视频背景或响应式布局规则。
- 不通过复杂内部选择器逐个改造控件形状；优先使用 manifest 已有的字体、输入框圆角和全局圆角能力。
- 不为四个主题抽象共享层；它们是现有主题契约下的独立数据与 CSS。
- 不发布、合并或执行生产环境操作。

## Areas of concern

- 品牌相似度过高可能造成官方合作误解：名称明确为风格主题，包内不使用标志或官方资产，描述不作认可声明。
- “华夏蓝”同时使用深蓝和红色，可能形成双主色：红色固定为交互强调色，深蓝只承担结构和文字层级。
- “机械工头”背景可能因高饱和画面压低可读性或过度贴近参考图：生成提示词锁定中部低细节、原创构图和禁用项，并对原图、预览和真实窗口逐项检查。
- 四个主题都支持两种外观，变量遗漏可能造成残留色：每个深色选择器绑定具体主题 ID，并在切换主题和外观后检查计算样式。
- 宋体或等宽字体在部分字符上可能缺字或度量变化：所有字体栈都提供苹方与通用族回退，并在中英文混排、代码块和长段落中检查行高与截断。
- 小圆角容易显得生硬，大圆角容易显得幼态：四套主题使用 0.50–1.15 的受控范围，并以真实窗口中的层级、点击区域和焦点可见性为准。
- 工作区存在大量无关改动：实现只拥有四个新主题目录、对应生成目录条目和本 workflow 目录，不回退、不格式化、不归因其他文件。

## Acceptance criteria

1. `intent.md` 和本 spec 均不包含用户明确禁用的两个词；变更目录和内部 ID 也不包含相关英文表达。
2. 四个主题目录均能通过作者工具 `check → preview → check`，且预览为 1200 × 675、内容与首选外观一致。
3. 四个 manifest 均被现有加载器识别，支持浅色和深色，语义色、raw RGB、预览、商店字段和有效 CSS 完整。
4. 四个主题的计算样式分别呈现约定的 UI/body/code 字体栈、字号比例和行高；断开网络后字体表现不变，主题包与 ZIP 中不存在字体文件。
5. 四个主题的输入框与主要表面分别呈现约定的圆角性格：“华夏蓝”和“机械工头”偏方，“代码仓库”为小圆角，“Claude 暖橙”为柔和中大圆角；焦点环、文字和点击区域不受损。
6. “机械工头”的 `bg.jpg` 为原创 16:9 横图，宽度至少 1920 px、无文字/标志/水印、文件不超过 1.5 MB；参考图不在包内，ZIP 只包含声明文件。
7. 网页同步后 catalog、数据库和四个 ZIP 均包含正确 ID、名称、版本、预览和校验值；连续同步两次无额外差异。
8. 现有 bundled-theme 精确测试通过，证明四个包可发现、可加载且生成有效 CSS；不要求与本变更无关的全仓库测试。
9. 四个主题分别在真实 DoubaoWork 的普通与窄窗口中应用成功，共八次视觉观察；侧栏、消息气泡、代码块、输入区、菜单、焦点和滚动区域可读且无残留色、溢出、冻结。
10. “机械工头”真实窗口中能看见机器监工叙事焦点，但聊天表面和遮罩保证正文对比度；画面不出现参考图文字、标志、角色或近似构图。
11. 验证记录包含命令、结果、预览尺寸与哈希、ZIP 内容、真实窗口截图、残余风险和偏差；最终 verdict 由 fresh-context verifier 或人工填写。

## Decision

等待产品与风险负责人确认四套视觉方向、第三方来源边界、原创背景约束和验收标准后，再进入工程计划阶段。
