# Intent: 新增华夏蓝、GitHub、Claude 与机器监工风格主题包

## Problem

现有主题库缺少四类辨识度强、适合不同工作氛围的界面：庄重清晰的中式门户风格、开发者熟悉的 GitHub 风格、温暖克制的 Claude 风格，以及带有黑色幽默的“机器人奴役人类”反乌托邦风格。用户目前无法在不修改应用代码的前提下直接选择这些视觉方案。

## Proposed outcome

新增四个可独立安装和预览的主题包：

- “华夏蓝”：以中国红、深蓝、白色和克制分隔线构成正式、清晰的中式门户浅色界面，不使用国徽、机关标识或暗示官方身份的文字。
- “代码仓库”：以 GitHub 界面的中性深灰层级、蓝色链接和绿色状态色构成高密度但易读的开发者深色界面，并在元数据中保留来源和许可边界。
- “Claude 暖橙”：以暖米白、陶土橙、深褐文字和克制边框构成安静、专注的浅色界面；只借鉴 Claude 产品的整体配色与编辑器气质，不使用品牌标志，也不暗示官方合作。
- “机械工头”：以高饱和复古综艺舞台、笨拙友好的机器人和忙乱打工人构成轻松荒诞的催工喜剧主题。用户提供的图片仅作为幽默节奏、舞台感和低保真画面质感的参考；主题使用新生成的原创插画，不复制原图人物、舞台纹样、文字、构图或可识别细节。

四个主题都沿用现有主题清单、预览和安装流程，不新增主题引擎分支。

## Affected users and systems

使用 Doubao Skin 主题库和网页主题商店的用户；受影响系统限于 `themes/` 下的新主题目录、由主题目录生成的网页目录数据，以及本变更的 workflow 证据。

## Constraints

- 视觉行为必须由主题 manifest 和 CSS 表达，不在桌面应用里添加主题专用逻辑。
- 新主题必须符合当前 v2 主题 schema、语义颜色变量、raw RGB 配对和选择器作用域约定。
- 主题变更后必须通过 `pnpm --dir apps/web sync` 重新生成网页目录，不能手改生成文件。
- 不修改 `/Applications/DoubaoWork.app`；真实效果仅通过仓库既有的 loopback CDP live 模式验证。
- 不打包国徽、机关标志、GitHub 或 Claude 商标图形，以及来源不明的品牌/图片资产。
- “机械工头”的原创背景通过项目允许的图像生成流程制作，作为氛围素材使用；画面保持滑稽、友善和无伤害，不使用真实人物肖像，不把用户提供的参考图写入主题包。
- 保留工作区里与本变更无关的已有修改。

## Out of scope

- 不修改主题引擎、安装协议、CDP 生命周期或桌面应用布局。
- 不复刻任何真实中式门户、GitHub 或 Claude 页面，也不声称得到任何机构、GitHub 或 Anthropic 官方认可。
- 除“机械工头”的一张原创生成背景插画外，不新增动态图标、背景摄影、外部字体、网络请求或新的第三方运行时依赖。
- 不发布、合并或跨越生产审批门槛。

## Success signals

- 主题库中出现四个名称、描述和配色可明确区分的新主题，且均可被现有加载器解析。
- 四个主题的预览能正确反映各自 manifest/CSS 的背景、文本、强调色和消息气泡层级；“机械工头”的原创背景在不妨碍文字可读性的前提下表达机器监工的讽刺主题。
- 网页目录同步后能发现四个新主题，已有主题目录不发生无关变化。
- 在真实 DoubaoWork 窗口中分别应用成功；正常与窄窗口下文本、输入区、侧栏和消息气泡保持可读，没有明显溢出、残留主题色或冻结。

## Open questions

- 请产品负责人确认四个拟定中文名称：“华夏蓝”“代码仓库”“Claude 暖橙”“机械工头”。

## Decision

等待产品负责人确认更新后的四主题范围和主题名称后，再进入设计规格阶段。
