# Intent: 增加 DMG、更新鲸鱼娘图标并修复标准版豆包透明度

## Problem

当前 macOS 构建只输出 `.app` 和 ZIP 压缩包，没有用户熟悉的 DMG 安装介质；用户需要手动解压并自行移动应用。与此同时，「鲸鱼娘」主题虽然配置了主图标，但现有棕色笑脸与蓝鲸少女主题的角色、颜色和俏皮气质不够一致，也没有用户期望的“馋嘴、流口水”表情记忆点。

标准版豆包还存在可复现的透明度偏差：工具滑块为 40% 时，运行时模型要求页面/侧栏 alpha 为 0.22/0.30，真实页面却计算为 0.72/0.82；整窗背景容器又与内容层继续合成，视觉上像多出一层深色蒙层，明显比预览更暗。当前证据显示，部分主题的深色 CSS 使用高优先级固定透明度，覆盖了滑块生成的运行时变量；同类写法不只存在于单一主题。

## Proposed outcome

让同一条 macOS 打包命令在保留现有 ZIP 的同时输出可校验的 DMG，DMG 中包含最终签名的“豆包主题.app”和指向 `/Applications` 的标准安装入口。使用内置 ImageGen 参考鲸鱼娘现有原创画面与项目内“馋嘴豆包”的表情方向，生成一枚透明背景、蓝鲸少女特征清晰、带轻微流口水神态的原创方形主题图标，并让鲸鱼娘浅色/深色变体共同使用它。

统一预览与真实注入的透明度优先级：滑块值必须成为所有背景表面最终生效的透明度来源，不再被主题内固定的深色表面 alpha 覆盖；同时针对标准版豆包比豆包工作更多的嵌套整窗容器校准合成层级，避免同一种表面色重复覆盖。修复应来自共享的主题运行时规则或数据清理，不为单个主题写专属补丁，并审计其他主题是否存在同类覆盖。

## Affected users and systems

- 下载或分发 macOS 构建的用户。
- `scripts/build-macos.sh` 的产物、校验和与可选签名/公证流程。
- `themes/gallery-whale-maid` 的主图标资源和 light/dark 变体声明。
- 由主题同步脚本生成的 Web 目录与主题卡片数据。
- 标准版豆包的主题注入、页面表面透明度与工具预览一致性。
- 所有含背景图和 `surfaceOpacity` 的主题，尤其是带深色变体及固定 `!important` 表面色的主题。
- 豆包工作现有主题注入行为的回归保护。

## Constraints

- DMG 必须复用已经完成构建、签名和图标编译的同一个 `.app`，不得重新拼装第二份应用。
- DMG 至少包含“豆包主题.app”和 `/Applications` 软链接，文件名继续体现 host/universal 架构标签，并生成独立 SHA-256 文件。
- 构建脚本失败时不得留下被误认为成功产物的半成品 DMG；挂载验证使用临时挂载点并可靠卸载。
- 保留现有 ZIP 输出、Ad-hoc/Developer ID 签名和可选公证能力，不改变正式 AppIcon。
- 图标使用内置 ImageGen 生成，参考图只用于角色、配色和表情方向；不得复制第三方品牌、文字或水印。
- 图标为透明背景的高分辨率 PNG，主体居中、轮廓简洁，在约 `20–52 px` 的实际预览尺寸仍能识别蓝鲸少女与馋嘴表情。
- 这是主题内的 `main` 图标，不替换“豆包主题”工具图标，也不修改豆包/豆包工作官方应用资源。
- 更新主题资源后必须运行 `pnpm --dir apps/web sync`，不手工修改生成目录。
- 先用回归测试固定“滑块值被深色主题固定 alpha 覆盖”的红灯，再修改实现；测试至少覆盖浅色、深色和自动模式。
- 不读取或输出聊天正文、Cookie、账号数据、附件或本地存储；真实页面验证仅采集元素尺寸、层级和计算样式。
- 不修改 `/Applications/Doubao.app` 或 `/Applications/DoubaoWork.app` 内的资源；只通过现有 loopback CDP 注入验证。
- 保留背景图本身及主题声明的轻量 veil；只消除未受滑块控制的重复表面着色，不把所有容器强制透明。
- 标准版豆包与豆包工作的 DOM 结构不同，允许使用目标能力标记选择共享 CSS 的适配规则，但不得复制整套主题或建立单主题分支。
- 全主题审计必须用结构化检查找出同类高优先级固定 alpha，避免只修复“馋嘴豆包”后在其他主题复发。
- 保存当前工作区中与本需求无关的未提交改动。

## Out of scope

- 自定义 DMG 背景、窗口坐标、许可证弹窗或第三方 DMG 制作依赖。
- 更换“豆包主题”应用的 Dock/Finder/AppIcon。
- 重画鲸鱼娘背景、预览图或其他导航/操作图标。
- 改变滑块的数值范围、交互方式或重新设计主题预览界面。
- 调整与透明度无关的主题配色、窗口尺寸或模型桥接协议。
- 发布、上传、公证生产产物或跨越发布审批门。

## Success signals

- `./scripts/build-macos.sh --universal` 同时产出 ZIP、DMG 及各自 SHA-256，DMG 能通过 `hdiutil verify`。
- 只读挂载 DMG 后可见“豆包主题.app”和有效的 Applications 软链接；内部应用通过严格 codesign、双架构和 Info.plist 检查。
- 鲸鱼娘的 light/dark `icons.main` 都指向新 PNG，主题加载、包校验和 Web 同步检查通过。
- 真实主题工具预览中，新图标在侧栏和主区域均清晰、无方形底色、无裁切，并与蓝色鲸鱼娘画面协调。
- 在标准版豆包中将“馋嘴豆包”设为 40% 时，页面/侧栏计算 alpha 与统一透明度模型相符，不再出现 0.72/0.82 的固定值或额外整窗深色蒙层；真实截图与工具预览在允许的原生布局差异内一致。
- 至少抽查“馋嘴豆包”“鲸鱼娘”及一套浅色背景主题；自动浅/深色切换后透明度仍由同一个滑块值控制。
- 结构化全主题检查不再发现会覆盖运行时透明度的高优先级固定表面 alpha；豆包工作的真实窗口保持原有效果，没有因标准版适配新增整窗透明或文字可读性回归。
- ImageGen 最终资产、使用提示词、自动化命令、截图、校验和与残余风险写入 verification.md。

## Open questions

无。“金玉娘”按当前主题目录中的「鲸鱼娘 / `gallery-whale-maid`」理解；“类似豆包流口水”只借鉴馋嘴神态和小尺寸构图，不复制另一个角色本身。“标准版豆包”按 `/Applications/Doubao.app` 与本机 loopback CDP 9223 目标理解，豆包工作仍作为必须通过的回归目标。

## Decision

等待产品负责人确认本意图后，再进入规格设计；本阶段不修改构建脚本、主题清单、图像资产或主题运行时代码。
